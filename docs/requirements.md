# ITパスポート学習Webアプリ 要件定義

## 1. 概要

ITパスポート学習者向けのWebアプリを作成する。
Java / Spring Boot を使用し、ポートフォリオとしてWeb公開できる形にする。

## 2. 目的

* ITパスポートの基礎知識を学習できる
* 演習問題で知識を確認できる
* 回答履歴から苦手ジャンルを把握できる
* 苦手ジャンルを重点的に学習できる
* 本番形式に近い実践演習ができる

## 3. 使用技術

| 区分      | 内容           |
| ------- | ------------ |
| 言語      | Java         |
| フレームワーク | Spring Boot  |
| 画面      | Thymeleaf    |
| DB      | PostgreSQL   |
| 教材管理    | Excel / xlsx |
| 公開      | Webデプロイ      |
| 管理      | GitHub       |

## 4. 対象資格

* ITパスポート

## 5. 学習ジャンル

### ストラテジ系

* 企業と法務
* 経営戦略
* システム戦略

### マネジメント系

* 開発技術
* プロジェクトマネジメント
* サービスマネジメント

### テクノロジ系

* 基礎理論
* コンピュータシステム
* 技術要素

## 6. 主要機能

## 6.1 基礎知識学習

ジャンル別に基礎知識を学習できる。

表示内容：

* ジャンル
* 単元名
* 基礎解説
* 重要語句
* よく出るポイント

## 6.2 演習問題

問題を解いて学習できる。

出題数：

* 25問
* 50問
* 100問
* エンドレス

仕様：

* 4択問題
* 回答後に正誤表示
* 回答後に解説表示
* 選択肢ごとに「なぜ正しいか / なぜ間違いか」を表示

## 6.3 苦手克服

回答履歴から苦手ジャンルを判定し、苦手ジャンルを中心に出題する。

判定基準：

|    正答率 | 判定    |
| -----: | ----- |
|  80%以上 | 得意    |
| 60〜79% | 普通    |
| 40〜59% | 苦手    |
|  39%以下 | かなり苦手 |

最低5問以上回答したジャンルを判定対象とする。

## 6.4 実践演習

本番形式に近い演習を行う。

仕様：

* 100問
* 制限時間120分
* 回答中は正誤を表示しない
* 終了後にまとめて採点
* 終了後に解説表示

出題比率目安：

| 分野      |  問数 |
| ------- | --: |
| ストラテジ系  | 35問 |
| マネジメント系 | 20問 |
| テクノロジ系  | 45問 |

## 7. 画面

必要な画面は以下。

| 画面   | 内容                   |
| ---- | -------------------- |

| 基礎知識 | ジャンル別の基礎知識表示         |
| 演習問題 | 問題演習、正誤判定、解説表示       |

| 実践演習 | 本番形式の100問演習          |
| 結果   | 正答率、ジャンル別結果、解説表示     |

## 9. 複数回答対応

通常は1つの正解を選ぶ。

ただし、問題ごとに複数回答も設定できる。

例：

| answer_type | correct_answers | required_answer_count |
| ----------- | --------------- | --------------------: |
| single      | 4               |                     1 |
| multiple    | 1,3             |                     2 |

判定は、選択した回答と正解セットが完全一致した場合のみ正解とする。

## 10. 保存データ

回答履歴として以下を保存する。

| 項目               | 内容               |
| ---------------- | ---------------- |
| user_id          | ユーザーID           |
| question_id      | 問題ID             |
| genre_id         | ジャンルID           |
| selected_answers | 選択した回答           |
| is_correct       | 正解 / 不正解         |
| mode             | 演習 / 苦手克服 / 実践演習 |
| answered_at      | 回答日時             |

## 11. 完成条件

以下ができれば初期完成とする。

* Web上でアプリを開ける
* ジャンル別に基礎知識を読める
* 25問 / 50問 / 100問 / エンドレスで演習できる
* 回答後に正誤と解説を表示できる
* 選択肢別に「なぜ違うか」を表示できる
* 回答履歴を保存できる
* ジャンル別正答率を表示できる
* 苦手ジャンルを表示できる
* 苦手ジャンル中心に出題できる
* 100問 / 120分の実践演習ができる
* Excelから問題・基礎知識を取り込める

## 12. 実装状況メモ

上記は初回に提示された要件定義そのものであり、実装を進める過程で以下の点は当初の想定から拡張・変更している。詳細は [db-design.md](db-design.md) を参照。

* **認証**: 「user_id」のみの想定だったが、実際にはログイン不要のゲスト利用(Cookie識別・30日で自動削除)と、メール+パスワードによる会員登録・ログイン・パスワードリセットを実装した。ゲストは会員登録すると回答履歴を引き継いだままアカウント化できる。
* **アカウント削除**: 要件には無いが、プライバシーへの配慮から追加実装した。
* **基礎知識データ**: 初期はジャンルごとに1本のサンプルのみだったが、IPA公式シラバス(Ver.6.5)の63項目と1対1で対応する63単元に拡充・再構成した(演習問題は現状20問のまま、今後拡充の余地あり)。
* **基礎知識の画面階層**: 当初は「ジャンル→そのジャンルの全単元を1ページに全文表示」だったが、目次が無く長大な1ページになり読みづらかったため、「ジャンル→単元一覧(タイトルのみ)→単元詳細(1本、前後の単元へのナビ付き)」の3階層に変更した(`/knowledge/{genreId}` が単元一覧、`/knowledge/{genreId}/{knowledgeId}` が単元詳細)。
* **用語集**: 要件には無いが、基礎知識の重要語句が用語名の羅列のままでは学習につながらないため追加実装した。重要語句(436語)を`terms`テーブルで管理し、基礎知識ページのキーワード欄から用語集詳細へ自動リンクする。一覧ページは検索ボックスに加え、ジャンル別/50音順(読み仮名ベース)の並び替えに対応する。当初はグローバルナビに独立項目として置いていたが、基礎知識と同じジャンル分類を持つ「もう一つの木」に見えて構造がわかりにくかったため、ナビからは外し、基礎知識ページに従属する導線(「用語集で調べる」リンク)に変更した。また用語集詳細ページは、由来する基礎知識単元の`body`をそのまま表示する(`terms.knowledge_id`で参照し、説明文を複製しない)ことで、一行の定義だけでは伝わらない文脈を補っている。
